1. Ingestion → extraction → renewal reminders

User shares a policy PDF/photo the same way they already share a payment receipt. One extraction call reads it; a scheduled worker watches the expiry date.

flowchart TD
    U["User"] -->|"shares policy PDF/photo\nvia share-sheet (reused)"| ING["Policy ingestion\nreceive_sharing_intent (reused)"]
    ING --> EXT["Extraction agent\nvision call, same shape as\nchat_global_image (reused pattern)"]
    EXT -->|"insurer, policy #, type,\npremium, issue + expiry date,\nsum insured, claims email"| DB["insurance_policies\n(new table)"]
    DB --> CONFIRM["Confirm sheet\nsame as transaction_confirm_sheet (reused pattern)"]
    CONFIRM -->|"user corrects misreads"| DB

    WORKER["Renewal reminder worker\nsame shape as nudge_engine /\nemail_reminder_worker (reused pattern)"] -->|"polls on a cycle"| DB
    WORKER -->|"N days before expiry"| TASK["tasks row + push notification\n(reused)"]
    TASK --> U

2. Filing a claim

Two ways in: the user asks directly, or the agent notices an incident while listening to a call. Either way it lands as a normal email draft — nothing sends until the user reviews it.

flowchart TD
    A["User: "file a claim for\nmy bike insurance""] --> AGENT
    B["Listen feature transcript:\n"...hit a pothole, bike's damaged..."\n(reused call-transcription pipeline)"] -->|"incident detected"| AGENT

    AGENT["Claim-filing agent\nnew tool in the AGENT_TOOLS loop\n(reused run_agent_tool_loop)"]
    AGENT -->|"match incident to policy"| DB["insurance_policies\n(new table)"]
    DB -->|"claims contact email,\npolicy #, sum insured"| AGENT
    AGENT -->|"ask for incident date,\ndescription, supporting photos"| USER2["User"]
    USER2 --> AGENT
    AGENT -->|"drafts claim email\nto insurer's claims address"| DRAFT["email_drafts row\n(reused as-is --\narbitrary recipient = draft, never auto-send)"]
    DRAFT --> CARD["EmailDraftCard\n(reused widget)"]
    CARD -->|"user attaches docs,\nreviews, taps Send"| SEND["send_plain_email\n(reused)"]
    SEND --> INSURER["Insurer's claims inbox"]
    SEND --> CLAIM["claims row: status = filed\n(new table)"]
    CLAIM -->|""what's the status\nof my claim?""| USER2
Your question

Yes — email is the right channel, and it costs almost nothing new to build. An insurer's claims address is exactly the "arbitrary, untrusted recipient" case send_email already drafts instead of sending immediately. The claim-filing agent's only real job is composing the draft correctly (right policy, right incident, right attachments) — the review-before-send safety net, the card UI, and the actual delivery are all infrastructure you shipped today.
